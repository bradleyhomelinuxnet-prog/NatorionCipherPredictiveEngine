a real parser, not new Function()

The v12 report's #1 Critical finding is that Ophis compiles .oph-controlled formula strings with new Function(). This page implements the recommended fix — a sandboxed recursive-descent evaluator over the Ophis grammar — and proves two things at load: it computes identically to the current engine on every shipped operation, and it rejects injection payloads that new Function() would execute. Open it; the tests run themselves.

Why the current regex filter isn't enough

The PSYFR rewrites gate input with a character-allowlist (blank the known tokens, reject leftover letters). That stops casual misuse, but it's a denylist in front of a live compiler — one new function alias, or a payload built only from allowed characters, and it's back to arbitrary code. A parser that only ever produces an AST it knows how to walk has no such escape hatch.
